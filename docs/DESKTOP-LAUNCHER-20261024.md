# 바탕화면에서 공무담 실행하기

컴퓨터를 켠 뒤 바탕화면의 **공무담 실행** 아이콘을 더블클릭합니다. 준비 창이 연결 완료를 확인하면 기본 브라우저에서 <https://gongmudam.visanu81.workers.dev>가 열립니다.

실행 버튼은 다음 순서로 동작합니다.

1. `127.0.0.1:8892`의 공무담 상태를 확인하고, 꺼져 있으면 별도 공개 시연 실행본으로 서버를 켭니다.
2. 같은 공개 주소가 응답하는지 확인하고, 연결되지 않았으면 공무담 전용 Cloudflare 터널을 켭니다.
3. 서버와 공개 주소의 정상 응답을 모두 확인한 뒤 브라우저를 엽니다.

서버·터널은 콘솔 창 없이 실행됩니다. 준비 창이나 브라우저를 닫아도 계속 동작합니다. 이미 실행 중이면 재사용하며, 준비 중 여러 번 눌러도 실행 잠금으로 중복 시작을 막습니다. PC를 끄면 업무 서버·AI 연결이 중단되며, 다시 켠 뒤 아이콘을 눌러야 합니다. Windows 로그인 시 자동 실행은 등록하지 않습니다.

로컬 AI를 사용하려면 Ollama와 사용할 모델도 실행 가능해야 합니다. 이 버튼은 AI 모델을 설치·다운로드하거나 Ollama를 따로 시작하지 않습니다.

## 바로가기 생성과 복구

현재 PC에는 `공무담 실행.lnk`를 생성했습니다. 다른 PC에서는 먼저 `install-service.bat`, Node.js 설치와 `npm ci`, 해당 Cloudflare 계정의 터널 연결 구성을 마친 뒤 `install-desktop-shortcut.bat`을 실행합니다. 다른 계정에서 이 저장소의 터널 ID만으로 공개 연결을 재현할 수는 없습니다.

바로가기는 설치 위치의 `service/.venv/Scripts/pythonw.exe`로 `tools/launch_gongmudam.py`를 실행합니다. 프로젝트를 옮기면 설치 파일을 다시 실행하세요. 이름이 같은 무관한 바로가기가 있으면 덮어쓰지 않고 번호를 붙입니다. 바로가기와 아이콘, 로그, 실행 상태, 인증정보는 GitHub에 올리지 않습니다.

## 연결되지 않을 때

준비 창에 실패 사유가 표시됩니다. **로그 폴더**를 눌러 `.local-runtime/launcher`의 `prepare.log`, `server-*.log`, `tunnel-*.log`를 확인합니다. 인터넷 연결이나 Cloudflare 로그인이 필요한 경우 `run-tunnel.bat`의 안내를 확인한 뒤 다시 누릅니다. 8892 포트를 다른 프로그램이 사용하면 해당 프로그램을 자동 종료하지 않고 안내합니다.

터널 연결에 실패해도 먼저 실행된 업무 서버는 유지합니다. 문제를 해결하고 다시 누르면 실행 중인 서버를 사용합니다. 브라우저만 열리지 않았으면 준비 창의 **공무담 열기**를 누르거나 위 공개 주소를 직접 여세요.

## 2026-10-24 검증 기록

물리적인 PC 재부팅은 수행하지 않았습니다. 공무담의 기존 서버와 전용 터널 연결 프로세스만 종료해 둘 다 꺼진 상태를 만든 뒤 실제 시작 경로를 실행했습니다. 다른 프로젝트 터널은 유지했습니다.

| 검사 | 실제 결과 |

| 바탕화면 바로가기 실행 | 실행 완료 기록과 기본 브라우저 열기 성공 확인 |

검사 명령은 프로젝트의 `service/.venv/Scripts/python.exe -m unittest discover -s tests -p test_launcher.py -v`입니다. 별도 테스트 패키지 설치 없이 실행됩니다. 연결 상태만 확인하려면 같은 Python으로 `tools/launch_gongmudam.py --status-only`를 실행합니다.

실제 시작 기록은 운영 PC의 `.local-verification/launcher-cold-start.json`, 바로가기 실행 후 상태는 `.local-runtime/launcher/startup-state.json`에 보관했습니다. 이 파일들은 로컬 경로와 실행 식별자를 포함하므로 저장소에는 포함하지 않습니다. 원본 v69 서비스와 기존 개인 데이터베이스는 변경하지 않았습니다.
