업무 달력

업무 달력으로 돌아가기

  • 월 보기를 기본으로 사용하며, 주 보기의 요일은 월요일부터 시작합니다. 이전·다음과 오늘 버튼 또는 날짜 선택으로 이동하고, 월·주·일·목록 보기를 고를 수 있습니다.
  • 종일 일정을 추가하거나 수정할 때 시작 날짜와 실제 마지막 날짜를 선택합니다. 두 날짜가 모두 일정에 포함됩니다. 시간 일정은 시작 시각과 종료 시각을 입력합니다.
  • 교육 취합 일정을 누르면 단계 패널에서 마감·미회신·서식·자료를 확인하고 마감을 수정할 수 있습니다. 출장 등 다른 원본 일정은 원래 업무를 열어 수정합니다. 직접 등록한 일정은 달력에서 추가하거나 수정할 수 있습니다.
  • 할 일·마감 알림은 접어서 둘 수 있습니다. 알림을 읽거나 미루는 동작은 원래 업무의 완료 처리가 아닙니다. 미룬 알림은 다음 날 오전 9시에 다시 표시되며, 알림 확인을 위해 달력 페이지를 열어 두세요.
  • 업무 종류·세부 업무는 달력과 할 일 목록에 함께 적용됩니다. ‘이번 주·마감 임박’ 등의 보기는 할 일 목록만 바꿉니다. ‘검색·날짜 이동·내보내기’를 펼치면 달력의 출처 필터를 사용합니다. 완료 여부를 알 수 없는 업무는 ‘완료 미확인’으로 구분합니다.
  • 저장한 보기로 반복해서 쓸 필터와 기간을 보관하고 다시 선택할 수 있습니다. 검색·빈 시간 찾기·현재 기간 내보내기도 사용할 수 있습니다.

새 PC에 설치하고 실행하기

  1. Windows x64와 Python 3.12 x64를 준비합니다. 제출 ZIP을 새 폴더에 풀고 서무비서 폴더를 엽니다. PowerShell에서 py -3.12 --version으로 Python 3.12 실행을 확인하세요. py를 찾지 못하면 Python Launcher도 함께 설치되어 있는지 확인하세요.
  2. install-submission.bat을 두 번 클릭합니다. PowerShell에서는 .\install-submission.bat을 실행합니다. 앱 의존성은 ZIP에 동봉된 24개 wheel로 오프라인 설치합니다. Python과 AI 모델은 별도로 준비해야 합니다.
  3. Ollama를 설치·실행하고 사용할 모델을 내려받습니다. 필요한 모델만 선택해 준비하세요. 
    ollama pull gemma3:4b
ollama pull llama3.2:3b
  4. 서무비서 폴더에서 PowerShell을 열어 모델 하나를 설정합니다. 아래 예시는 Ollama의 로컬 호환 API 주소를 사용합니다.

    Gemma 3 4B

    .venv\Scripts\python.exe tools\configure_submission_model.py --profile local_gemma --base-url http://127.0.0.1:11434/v1 --model gemma3:4b --json-object

    Llama 3.2 3B

    .venv\Scripts\python.exe tools\configure_submission_model.py --profile local_llama --base-url http://127.0.0.1:11434/v1 --model llama3.2:3b --json-object
  5. start-submission.bat을 두 번 클릭합니다. PowerShell에서는 .\start-submission.bat을 실행합니다. 실행 창을 열어 둔 채 브라우저에서 http://127.0.0.1:8781/start.html?v=67을 엽니다. 모델 설정 전에는 실행기가 오프라인 안내 후 종료하므로 설정을 마친 다음 다시 시작하세요.

첫 화면에서 업무 시작하기

  • 새로 질문하기에 할 일을 적으면 답변과 근거를 확인할 수 있습니다. 이어서 처리하려면 답변 위쪽의 업무 시작 동작을 선택해 알맞은 출장·취합·자료 정리 화면으로 이동합니다. 입력만으로 업무가 확정되거나 저장되지는 않습니다.
  • 하던 업무 이어하기에서 저장한 업무를 다시 열어 남은 일을 진행합니다. 브라우저를 새로고침해도 이전 질문이 다시 전송되지는 않습니다.
  • 출장·취합·자료 정리 화면의 상단 업무 시작을 누르면 첫 화면으로 돌아옵니다.
  • 자료 설정은 첫 화면 아래의 실행환경·설정을 펼쳐 볼 수 있습니다. 접혀 있어도 업무 시작과 저장 업무 이어하기를 사용할 수 있습니다.

업무 단계의 저장은 제출·승인을 뜻하지 않습니다. 취합 단계의 완료 확인은 담당자가 직접 하고, 담당자 검토·승인과 구분해 주세요.

모델 연결과 시험 응답 확인

첫 화면의 실행환경·설정을 펼치면 선택한 모델, 서버 연결 상태, 최근 시험 응답 상태가 따로 표시됩니다. ‘서버 연결됨 · 모델 확인’은 연결 상태이며 시험 응답 성공 표시와 다릅니다.

실제 응답 확인을 누르면 합성 시험 질문을 선택한 로컬 모델에 보내 응답 상태를 확인합니다. 모델을 바꾼 뒤에는 새로고침해 선택 상태를 확인하고 이 버튼으로 변경한 모델의 응답을 다시 시험하세요. Ollama가 실행 중이고 선택 모델이 준비되어 있어야 합니다.

출장정산

  1. 새 출장 흐름에서 출장 정보와 증빙을 확인합니다. 예시를 다시 시작할 때에는 새 출장을 선택합니다.
  2. 거래와 원본 자료를 대조하고 계산 조건을 확인합니다. 규정 기준 계산 · 근거 확인을 실행한 뒤 각 항목의 계산 근거와 등록 자료를 펼쳐 읽습니다.
  3. 검토한 상태로 초안을 저장합니다. 초안은 담당자 확인을 위한 자료입니다. 업무를 저장한 뒤 새로고침해도 질문이 다시 보내지지 않으며, 저장 업무는 첫 화면의 하던 업무 이어하기에서 다시 엽니다.

교육·자료 취합

교육 취합 예시를 채운 뒤 교육명·일정·회신 마감·대상 부서를 확인하고 업무를 만듭니다. 기본 진행표는 안내 확인 → 희망자 모집 → 회신 취합 → 누락·중복 검토 → 명단·결과보고의 5단계입니다.

각 단계의 완료 확인사항을 살펴보고 담당자가 확인한 뒤 완료 처리합니다. 완료된 단계에 다음 단계가 있으면 다음 단계: … 버튼으로 이동합니다. 회신 자료나 명단의 행을 바꾸면 누락·중복을 다시 확인하고 취합본을 갱신해 저장하세요.

업무자료 정리

업무자료 정리에서 폴더를 선택하고 파일 분류 제안을 살펴봅니다. 분류와 연결 상태를 원문 자료에 대조해 필요한 항목을 확인한 뒤 결과를 저장합니다.

폴더 업로드는 사본을 가져옵니다. 이 PC의 폴더를 직접 연결하면 해당 경로를 읽고, 별도로 감시를 켰을 때 변경 제안을 확인할 수 있습니다. 분류 확인은 원본 파일의 이동·이름 변경을 실행하지 않습니다.

자료 기준일과 검증 결과 확인

이 페이지에는 법령 확인 날짜나 검증 건수를 고정해 적지 않습니다. 계산에 쓰이는 실제 근거와 등록 자료를 확인하고, ZIP 압축 폴더에서 먼저읽기.txt와 verification 보고서를 열어 이번 패키지의 기준일·검증 환경·검토 대기 상태를 확인하세요. 앱 서버에서는 TXT 파일이 열리지 않으니 압축을 푼 폴더에서 직접 여세요.

법령 자료는 모델 학습 가중치가 아니라 원문과 추출 자료, 출처 ID 및 해시를 보존해 복원하는 자료입니다. API 키와 모델 가중치는 제출 패키지에 포함되지 않습니다. 복원은 동봉된 인증 기간을 그대로 사용하며 기간을 늘리지 않습니다.

등록 자료와 계산 근거를 직접 확인하세요. 이 앱 안내나 모델 응답만으로 법령 적용의 정확성이 보장되지는 않습니다. 출장 계산·교육 취합 결과는 담당자가 원자료와 조건을 검토한 뒤 처리해야 합니다.

종료와 다시 실행

서무비서 실행 창에서 Ctrl+C를 눌러 종료합니다. 다시 실행할 때는 start-submission.bat을 두 번 클릭하거나 PowerShell에서 .\start-submission.bat을 실행합니다. 포트 8781이 이미 사용 중이면 다른 실행 창을 확인하고 종료한 뒤 다시 시작하세요.
